# 台灯舵机通信协议

本文档总结 XiaoLamp 当前板级舵机总线实现。协议代码位于
`main/boards/waveshare/apple-lamp-ov3660/lamp_bus_protocol.*`，ov2640 板型使用相同的协议实现。
文档描述的是固件当前实际使用的串行总线格式，不等同于所有舵机型号的完整指令集。

## 1. 物理接口与串口参数

| 项目 | 配置 |
| --- | --- |
| UART | UART0 |
| 波特率 | 115200 |
| 数据格式 | 8 数据位、无校验、1 停止位（8N1） |
| 硬件流控 | 禁用 |
| TX | ESP32-S3 GPIO43 |
| RX | ESP32-S3 GPIO44 |
| 设备数量 | ID 1 至 ID 5 |
| 逻辑电平 | 3.3 V |

BusLinker v3.0 接线为 GPIO43 → J1 第 1 脚 EX_TX、GPIO44 ← J1 第 2 脚 EX_RX，
控制器与舵机电源必须共地。J8 使用 1–3、2–4 跳帽。舵机需要独立供电；逻辑接口不是舵机
动力电源。

UART0 被舵机总线占用时，固件使用原生 USB Serial/JTAG 输出日志，并禁用次级 UART 控制台。

## 2. 帧格式

所有请求和响应均使用小端序参数，并采用以下字节布局：

```text
+--------+--------+-----+--------+---------+----------------+----------+
| 0x55   | 0x55   | ID  | LENGTH | COMMAND | PARAMETERS ...  | CHECKSUM |
+--------+--------+-----+--------+---------+----------------+----------+
    1        1       1       1        1          N                1 byte
```

### 2.1 字段说明

- `0x55 0x55`：固定帧头。
- `ID`：舵机地址。当前应用使用 1–5；协议解析器允许 1–253。
- `LENGTH`：从 `ID` 后的协议字段计算出的长度，当前实现为
  `参数字节数 + 3`。因此无参数请求的 `LENGTH` 为 `3`。
- `COMMAND`：命令码。
- `PARAMETERS`：命令参数，低字节在前（little-endian）。
- `CHECKSUM`：`ID`、`LENGTH`、`COMMAND` 和所有参数字节之和的按位取反，只保留 8 位：

```text
checksum = ~(ID + LENGTH + COMMAND + sum(PARAMETERS)) & 0xff
```

校验通过时，以下字节之和应为 `0xff`：

```text
ID + LENGTH + COMMAND + PARAMETERS + CHECKSUM = 0xff (mod 256)
```

### 2.2 长度计算

设参数长度为 `N`：

```text
LENGTH = N + 3
完整帧长度 = LENGTH + 3 = N + 6
```

例如，读取命令没有参数，帧长度为 6 字节：

```text
55 55 ID 03 COMMAND CHECKSUM
```

## 3. 读请求

读请求统一为无参数帧：

```text
55 55 ID 03 COMMAND CHECKSUM
```

当前代码允许构造的读命令及返回参数长度如下：

| 命令码 | 返回参数长度 | 当前含义 | 数据格式 |
| ---: | ---: | --- | --- |
| `14` | 1 | 协议层允许读取，当前应用不采集 | 单字节 |
| `21` | 4 | 位置限位 | `limit_min`、`limit_max`，各 16 位无符号小端整数 |
| `26` | 1 | 温度 | 单字节，当前直接作为摄氏度使用 |
| `27` | 2 | 电压 | 16 位无符号小端整数，当前直接作为 mV 使用 |
| `28` | 2 | 当前位置 | 16 位小端整数，按有符号 `int16_t` 解释，单位为舵机 tick |
| `30` | 4 | 运行模式 | 协议层期望 4 字节；当前应用使用返回参数的第 1 字节 |
| `32` | 1 | 扭矩状态 | `0` 表示关闭，`1` 表示开启 |

当前本地状态采集任务实际轮询：

- 每轮读取 5 个舵机的 `CMD 28` 位置；
- 再从 `CMD 26`、`CMD 27`、`CMD 30`、`CMD 32` 中轮询一个遥测字段；
- `CMD 21` 由硬件运动执行器在需要位置限位时读取。

读取响应必须同时满足以下条件才会被接受：

1. 帧头、长度和校验和正确；
2. 响应 `ID` 与请求的舵机 ID 一致；
3. 响应 `COMMAND` 与请求命令一致；
4. 参数长度与该命令的预期长度一致。

超时、校验错误、回显或其他舵机的响应不会更新状态。位置反馈超过约 1.5 秒未刷新时，
该舵机的位置被视为过期；五个舵机的位置都新鲜时，应用状态才会报告 `available=true`。

## 4. 写请求

当前写入封装只允许以下四类请求，并且只允许单个舵机 ID，不支持广播：

| 命令码 | 参数 | 参数说明 | 固件用途 |
| ---: | --- | --- | --- |
| `1` | 4 字节 | `position_lo position_hi time_lo time_hi` | 发送目标位置和运动时间 |
| `12` | 无 | 无 | 停止/卸载动作 |
| `29` | `00 00 00 00` | 固定四个零字节 | 进入运动前的模式切换 |
| `31` | 1 字节 | `0` 或 `1` | 关闭或开启扭矩 |

### 4.1 CMD 1：位置控制

参数布局：

```text
position_lo position_hi time_lo time_hi
```

- `position`：16 位无符号小端 tick，当前固件限制为 `0..1000`；
- `time`：16 位无符号小端时间值，当前固件限制为 `0..30000`；
- 发送前，应用会根据模型、安装方向、零点和舵机限位将目标角度转换为 tick；
- 当前实现按 ID 1 至 ID 5 逐个发送，不使用广播帧。

### 4.2 CMD 12：停止

无参数。执行停止时，当前硬件执行器会分别向 ID 1–5 发送一帧 `CMD 12`，
而不是发送广播命令。

### 4.3 CMD 29：模式切换

参数必须严格为四个零字节：

```text
00 00 00 00
```

启用扭矩前，固件先读取 `CMD 30`；若模式不是 `0`，则发送 `CMD 29`，
然后再次读取 `CMD 30` 确认模式已变为 `0`。

### 4.4 CMD 31：扭矩控制

参数只有一个字节：

```text
00  # 关闭扭矩
01  # 开启扭矩
```

发送后必须读取 `CMD 32` 确认返回值与请求一致。确认失败时，动作被视为失败，不会伪造
完成结果。

## 5. 帧示例

以下示例中的校验和按本文公式计算。

### 5.1 读取 ID 1 的当前位置（CMD 28）

请求：

```text
55 55 01 03 1C DF
```

其中 `0x1C` 是十进制 28，校验为：

```text
~(0x01 + 0x03 + 0x1C) & 0xff = 0xdf
```

假设返回位置为 `0x01F4`（500 tick），响应可表示为：

```text
55 55 01 05 1C F4 01 E8
```

响应中的位置参数为低字节 `F4`、高字节 `01`。

### 5.2 向 ID 1 发送位置和时间（CMD 1）

假设位置为 500 tick、时间为 1000：

```text
55 55 01 07 01 F4 01 E8 03 16
```

参数为：

```text
F4 01  # position = 500
E8 03  # time = 1000
```

## 6. 接收解析与错误处理

解析器是流式解析器，可处理一次读取只收到半帧或一次读取包含多帧的情况。它会：

- 丢弃不以 `55 55` 开头的数据；
- 拒绝 `ID > 253`、`LENGTH < 3` 或 `LENGTH > 32` 的帧；
- 等待完整帧到齐后再校验；
- 校验失败时丢弃一个字节并继续寻找下一个帧头；
- 仅输出通过全部检查的 `Packet{ID, COMMAND, PARAMETERS}`。

应用层读取默认等待 400 ms；硬件执行器的确认读取最多重试一次，中间等待 40 ms。
读取失败会记录 `read_failures` 和 `last_error`，不会把失败当作成功，也不会在只读探测
路径中写入运动命令。

## 7. 当前实现边界

- 协议封装明确拒绝预置动作、广播、未知命令以及不符合长度/范围的写请求。
- 只读探测固件的 `motion_enabled=false`，不会发送位置、模式或扭矩写入。
- 硬件运动固件只有在反馈、位置限位和扭矩状态确认通过后才继续动作。
- 舵机总线由外部 BusLinker 和独立电源提供；USB Serial/JTAG 仅用于日志和控制台。
- 任何新的命令码、参数含义或电气连接变更，都应先核对实际舵机控制器文档和硬件实测，
  不应仅凭本文件推断所有兼容舵机的行为。
