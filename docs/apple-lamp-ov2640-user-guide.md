# OV2640 delivery 使用说明

本文面向使用 `apple-lamp-ov2640-xiaozhi-delivery` 固件的操作者。当前版本是
带 OV2640 摄像头、语音交互、局域网测试页和用户动作库的台灯机器人。源码中的跟书
仍是不完善的实验功能，不能作为交付或课程使用能力。
除非特别说明，本文不适用于 `omni-poc`、`edge-runtime`、`local-*` 或旧 OV3660
固件。

## 1. 使用前确认

### 1.1 硬件

- ESP32-S3R8，16 MB Flash，8 MB PSRAM；
- OV2640 按板卡接线连接，SCCB 使用 GPIO4/5；
- 外接 I2S 功放接 GPIO38/39/40，SD 拉高；
- 外接 PDM 麦克风接 GPIO41/42；
- 舵机总线接 GPIO43/44，所有设备共地；
- 机械臂和摄像头固定可靠，舵机有独立且足够的电源。

不要在未确认供电、共地和串口方向前通电。本文使用的交付版本启动时不自动上力，
但机械运动仍必须由操作者在安全范围内观察。

### 1.2 固件角色与构建

使用 ESP-IDF 6.1（最低支持 6.0.1，IDF 5.x 不支持）：

```powershell
python scripts/build_lamp_variant.py --board apple-lamp-ov2640 --role xiaozhi-delivery
```

如果只归档已有构建：

```powershell
python scripts/build_lamp_variant.py --board apple-lamp-ov2640 `
  --role xiaozhi-delivery --archive-only
```

烧录必须显式提供实际串口，`COM8` 仅为示例：

```powershell
python scripts/build_lamp_variant.py --board apple-lamp-ov2640 `
  --role xiaozhi-delivery --archive-only --flash --port COM8
```

烧录前备份 Wi-Fi、安装映射、标准姿态和用户动作。首次迁移不能只刷应用：
delivery 使用 `0x800000` 起的 7 MiB 资源区和 `0xF00000` 起的 1 MiB
`lamp_actions` 分区，必须使用同一归档中的完整镜像。不要把整片擦除当作常规升级。

## 2. 首次配网与小智绑定

1. 启动设备，等待串口日志中的 `Xiaozhi-*` 配网热点。
2. 手机连接该热点，打开配置页，填写家庭 Wi-Fi。
3. 等待设备切换到 STA；从日志取得设备 IP 和激活提示。
4. 手机/电脑切换回能访问互联网的网络，打开小智官方控制台。
5. 登录账号并添加设备，输入设备播报的绑定验证码。
6. 绑定完成后唤醒设备，确认它能听到语音并播放回答。

设备的配网热点名和联网主机名可能因 SoftAP/STA MAC 不同而不同。设备 IP 变化时，
以串口打印的 `http://<设备IP>:8080/` 为准，不要使用旧 IP 或 `127.0.0.1`。

## 3. 日常语音、相机与视觉

### 3.1 普通对话

说唤醒词后等待提示，再提问或下达动作请求。典型链路是：

```text
唤醒词 -> 语音上行 -> 小智 ASR/大模型 -> TTS/工具调用 -> 设备播放或执行
```

语音播放或对话进行中不要同时进行 Flash 初始化、示教或强制上力。动作请求应使用
自然语言描述开放能力，例如“播放问候动作”，不要要求模型发送角度、tick 或 UART
帧。

### 3.2 拍照和按需视觉

当前相机按需工作，不是持续后台摄像头。用户明确要求“看看/拍照描述”时，使用
当前会话提供的相机能力；拍照时保持目标在镜头内并等待回答。自拍描述不代表身份
识别或人脸注册验证。

跟书当前不可交付，不能把网页中的视觉 URL/Token、JPEG 预览或跟书按钮当作可用功能。
如需继续研发，只能在隔离的实验设备上验证实际上传图像、颜色、镜像和目标位置，不得
作为用户操作流程或课程环节。

## 4. 打开局域网网页

1. 让手机/电脑与设备连接同一局域网。
2. 在浏览器打开串口日志给出的 `http://<设备IP>:8080/`。
3. 首页会注入设备令牌；后续 API 由页面自动携带令牌。
4. 断开或更换网络后重新从日志确认 IP，不要手工复用旧令牌。

网页主要区域：

- **状态/诊断**：查看执行器、反馈新鲜度、堆内存、任务和交付状态；
- **配置/标定**：查看模型、安装方向、偏置和限位；
- **示教/动作库**：创建、导入、导出、播放和删除用户动作；
- **跟书实验**：源码保留配置/预览/停止入口，仅供开发排查，不是交付功能；
- **MCP/日志**：列出工具、调用工具、查看对话和任务历史。

网页 API 是异步的：看到请求被接受不等于动作已完成，必须继续查看 job 和 hardware
task 回执。

## 5. 示教与播放用户动作

### 5.1 示教

1. 先保存并重启确认安装方向、偏置和标准姿态；用很小幅度验证各轴。
2. 在网页点击开始示教，等待状态变为 `recording`，并确认五轴真实卸力。
3. 手动移动灯臂，停稳后点击记录关键帧；至少 2 帧，最多 32 帧。
4. 设置参与关节、段时长、英文 ID、名称、描述和结束模式。
5. 结束示教并保存。保存时设备会检查反馈、安装绑定、路径、限位和文件格式。
6. 保存后保持手动占用；需要播放时再点击“保持当前位置并使能”，等待真实使能确认。

未保存草稿只在本次开机有效。不要在示教期间让语音或网页同时上力，也不要在设备
未确认卸力时手掰灯臂。

### 5.2 播放与验证

1. 先从动作目录确认 `valid` 和 `compatible`。
2. 在两个不同的安全起点试播同一个动作，确认相对变化一致。
3. 危险起点、反馈过期、安装绑定不匹配或越过限位时，应拒绝且不先发运动。
4. 小智可通过 `self.lamp.list_user_actions` 查询目录、通过
   `self.lamp.play_user_actions` 播放 1–16 个动作。
5. 保存 `job_id`，再查询 delivery 状态；若有 hardware task，再查询硬件任务。
6. 只在硬件反馈确认后认为机械动作完成。

动作保存到独立 LittleFS 动作区，最多 24 个动作，每文件上限 12 KiB。固件升级和
分区迁移前先导出动作；损坏文件不会自动格式化或删除。

### 5.3 导入、导出和编排

可以导出 JSON 后编辑描述、段时长和增量，再导入更新。不能伪造安装绑定版本来
绕过安装确认。动作编排最多 1–16 个用户动作，整组最多 60 秒；导入、删除、初始化
和 Flash 更新前必须停止跟书、确认音频空闲并手动卸力。

## 6. 跟书实验状态（不可交付）

跟书功能尚未完成，当前版本不得交付、不得作为课程依赖，也不得据此承诺自动跟随。
下列内容只是源码已有的实验入口和待研发方向，不是使用说明：

1. 仅在开发实验设备上配置视觉地址和 Token；
2. 放置一本书，先只观察一次，检查 JPEG 预览及模型返回的目标中心。
3. 用网页 ±3° 小幅测试确认书在画面右侧对应的 Yaw 符号、书在画面下侧对应的
   灯头 Pitch 符号。该符号不是舵机 direction 的名称。
4. 在跟书区保存方向、死区、比例增益和单步上限；默认未确认时不能启动。
5. 点击“切换自主控制并保持当前位置使能”，等待真实力矩确认。
6. 启动跟书，缓慢移动书，确认死区内不抖、目标丢失不乱转。
7. 通过网页或 `self.lamp.stop_book_tracking` 停止实验；停止会使旧视觉结果失效。

以下情况会停止或拒绝继续：网络/HTTP/JSON 连续失败、目标丢失、反馈不新鲜、越过
限位、普通用户接管、动作请求、卸力或休息。跟书不会自动上力、自动恢复或自动搜书。
它不是任意姿态下的高频视觉伺服。

## 7. 停止、休息与故障处理

### 7.1 立即停止

- 网页优先点击停止；
- 小智调用 `self.lamp.stop_book_tracking` 停止跟书，或使用设备已有停止工具；
- 需要人手接管时先停止，再确认支撑力矩状态；
- 发现机械异常时断开运动授权并切断舵机电源，不能等待语音回复。

停止通常保留支撑力矩；卸力和休息是不同操作。重新启动跟书或动作前必须明确重新
使能并确认反馈。

### 7.2 常见问题

| 现象 | 检查 |
| --- | --- |
| 找不到配网热点 | 检查供电、串口启动日志和是否仍保存旧 Wi-Fi；必要时按交付流程重新配置 |
| 能配网但不能绑定 | 确认设备已连接互联网、验证码未过期，并以当前设备身份重新添加 |
| 语音无输入 | 检查 PDM CLK/DATA、共地、麦克风供电和是否处于播放/会话状态 |
| 有回答但无声音 | 检查 I2S BCLK/LRCLK/DATA、功放供电和扬声器连接 |
| 网页打不开 | 电脑与设备是否同网、IP 是否变化、是否把 USB 当成网络桥 |
| 动作不可用 | 查看安装绑定、反馈新鲜度、力矩确认、限位和动作文件兼容性 |
| 跟书不动 | 先看 JPEG/视觉 JSON、Token/额度、目标置信度和跟书方向参数 |
| 任务一直处理中 | 分开查询 delivery job 与 hardware task；网络结果 `unknown` 时不要重复运动 POST |

遇到问题时导出对话记录、网页日志和交付诊断 JSON。用户语音、图片、Token 和
私密场景描述不要提交到 Git。

## 8. 当前功能与验收边界

### 已实现

- OV2640 按需 JPEG 取帧、语音会话、设备端 MCP；
- 8080 同源令牌保护的状态、配置、MCP 和 delivery API；
- 五轴真实反馈、示教关键帧、相对增量动作库、导入导出和编排；
- 低频 Yaw/Pitch 跟书、JPEG 预览、失败暂停和旧结果失效；
- 有界队列、任务回执、限位/安装/反馈/权限校验。

### 仍需实机或云端验收

- 云端视觉地址/Token 的权限、额度和持续请求稳定性；
- 图像方向、机械 Yaw/Pitch 符号与真实安装姿态；
- Flash 断电写入、满容量、损坏文件和分区迁移；
- 连续两小时语音、跟书、网页并发运行的堆内存和恢复能力；
- 任意 Roll/极端姿态、自动搜书、身份识别或高频视觉伺服。

构建通过、工具返回成功或语音说“完成”都不能替代上述验收；在完成这些工作前，跟书
仍不能交付。
